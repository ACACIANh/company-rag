# 코드 리뷰 가이드

## 목적
코드 리뷰는 품질 향상과 지식 공유가 목적이다. 사람이 아닌 코드를 리뷰한다.

## PR 작성자 가이드
- PR 크기: 300줄 이하 권장 (초과 시 분리 고려)
- PR 제목: 컨벤셔널 커밋 형식 (feat:, fix:, refactor: 등)
- 설명란: 변경 이유(Why)와 주요 설계 결정 명시
- 셀프 리뷰 후 올리기
- 리뷰어 최소 1명 지정 필수

## 리뷰어 가이드
- 48시간 이내 초기 피드백 제공 (업무일 기준)
- 코멘트 분류 표시:
  - [블로커]: 머지 전 반드시 수정
  - [제안]: 선택적 개선사항
  - [질문]: 이해를 위한 질문
  - [칭찬]: 잘한 점 명시

## 리뷰 체크리스트
- [ ] 기능이 요구사항을 충족하는가
- [ ] 테스트가 충분한가 (엣지 케이스 포함)
- [ ] 보안 취약점이 없는가
- [ ] 성능 문제가 없는가
- [ ] 코드가 기존 패턴을 따르는가

## Approve 기준
최소 1명의 Approve가 있어야 머지 가능하다.
팀장은 본인 PR에 본인 Approve 불가.
