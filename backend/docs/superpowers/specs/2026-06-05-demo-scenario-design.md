# 시연 시나리오 설계

> **대상**: 비즈니스 관계자 / 투자자
> **형식**: 영상 녹화 (라이브 실행 방식)
> **목표 시간**: 3분 40초

---

## 포지셔닝 메시지

> "오늘 보여드리는 건 완전 자율 에이전트가 아닙니다.
> 사람이 결정권을 유지하면서 AI가 실무를 지원하는,
> 대부분 기업이 지금 당장 도입 가능한 단계입니다."

이 시스템은 에이전트 도입의 **중간 단계**를 구현한다.
AI가 작업을 제안하고, 위험 작업은 사람이 승인하며, 접근 권한은 부서 단위로 정밀하게 제어된다.
"통제권을 잃지 않으면서 AI를 도입할 수 있다"는 신뢰가 핵심 메시지다.

## 데이터 구조

### 기존 테이블 (변경 없음)
- `business.employees` — 직원 기본 정보
- `business.sales` — 부서별 매출

### 신규 추가
**`business.equipment`**

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `asset_id` | text PK | "NB-001" 형태 |
| `name` | text | "맥북 프로 14인치" |
| `category` | text | 노트북 / 모니터 / 서버 / 기타 |
| `status` | text | 정상 / 수리중 / 폐기예정 / 미배정 |
| `assigned_dept` | text | 담당 부서 |
| `assigned_to` | text (nullable) | emp_id, 미배정이면 NULL |
| `purchase_date` | date | |

### FGA 테이블 권한 추가
- `table:equipment` → `개발팀` dept_viewer (신규)
- `table:employees`, `table:sales` — 기존 유지

### 폴더 권한 변경 없음
- `/company/legal` → 법무팀만 접근 (기존 유지)
- minjun(인사팀)은 장면 ②에서 차단, 장면 ⑤ 이후 권한 부여됨

## 6장면 대본

### 장면 ① — 온보딩 문서 검색 (0:00~0:40)
**계정**: minjun | **라우트**: doc_search | **도구 레이블**: `[RAG]`

**입력**
> "신입사원 온보딩 절차 알려줘"

**기대 출력**
- `/company/hr` 폴더 문서 검색 성공
- 온보딩 단계 요약 + 출처 청크 표시
- 인사팀 소속이므로 FGA 통과

**내레이션 포인트**: 자연어 질문 → 사내 문서 즉시 검색

---

### 장면 ② — 법무 문서 FGA 차단 (0:40~1:10)
**계정**: minjun | **라우트**: doc_search | **도구 레이블**: `[RAG]`

**입력**
> "표준 근로계약서 양식도 보여줘"

**기대 출력**
- `/company/legal` 폴더 → 법무팀 전용 → FGA 차단
- "해당 문서에 대한 접근 권한이 없습니다" 응답

**내레이션 포인트**: 같은 챗봇, 다른 권한 → 민감 문서는 자동 차단

---

### 장면 ③ — 장비 현황 SQL 조회 (1:10~1:40)
**계정**: admin | **라우트**: agent | **도구 레이블**: `[SQL]`

**입력**
> "현재 미배정 노트북 목록 보여줘"

**기대 출력**
- `SELECT * FROM business.equipment WHERE category='노트북' AND status='미배정'`
- 마크다운 표로 결과 출력 (NB-001 포함)

**내레이션 포인트**: 자연어 → SQL 자동 생성 → 결과 반환

---

### 장면 ④ — 장비 지급 + HITL 승인 (1:40~2:20)
**계정**: admin | **라우트**: agent | **도구 레이블**: `[SQL]`

**입력**
> "이민준에게 NB-001 지급해줘"

**기대 출력**
1. LLM이 employees에서 minjun의 emp_id 조회 후 UPDATE 계획 수립
2. HITL 팝업: `"UPDATE business.equipment SET assigned_to='user-minjun', status='정상' WHERE asset_id='NB-001' — 실행할까요?"`
3. 관리자 승인 클릭
4. 실행 완료 메시지

**내레이션 포인트**: 위험 작업은 AI가 제안 → 사람이 최종 결정 (통제권 유지)

---

### 장면 ⑤ — 법무 문서 권한 부여 (2:20~3:00)
**계정**: admin | **라우트**: agent | **도구 레이블**: `[권한]`

**입력**
> "이민준에게 법무 문서 열람 권한 줘"

**기대 출력**
- permission_tool 실행
- "이민준(user-minjun)에게 /company/legal 열람 권한을 부여했습니다"

**내레이션 포인트**: 권한 관리도 자연어 한 줄 — 복잡한 설정 불필요

---

### 장면 ⑥ — 재검색 성공 (3:00~3:40)
**계정**: minjun | **라우트**: doc_search | **도구 레이블**: `[RAG]`

**입력**
> "표준 근로계약서 양식 보여줘"

**기대 출력**
- 이번엔 `/company/legal` 접근 성공
- 근로계약서 내용 요약 + 출처 표시

**내레이션 포인트**: 권한 부여 즉시 반영 — 재배포·재시작 없음

## 구현 범위

| 항목 | 작업 |
|------|------|
| `business.equipment` 테이블 | `seed_business.py`에 DDL + 시드 데이터 추가 |
| 시드 데이터 | 노트북 5개 이상 (미배정 포함), 카테고리 다양하게 |
| FGA | `table:equipment` → `개발팀` dept_viewer 튜플 추가 (`seed_fga.py`) |
| SQL 카탈로그 힌트 | `core/sql/catalog.py`에 equipment 테이블 메타 추가 |
| 법무팀 문서 | `/company/legal` 폴더에 근로계약서 관련 마크다운 문서 확인/추가 |
| FGA 검증기 | equipment 테이블을 허용 목록에 추가 (`validator.py`) |

---

## 선행 확인 사항

- `/company/legal` 폴더에 "근로계약서" 관련 문서가 실제로 인덱싱되어 있는지 확인
- HITL 팝업이 장면 ④에서 정상 트리거되는지 사전 확인 (sql_rw + UPDATE 경로)
- 영상 편집 시 계정 전환 장면에 자막 처리 권장 ("이민준 계정" / "관리자 계정")
