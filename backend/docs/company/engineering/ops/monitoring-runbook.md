# 모니터링 런북

## 목적
서비스 상태를 모니터링하고 알람 발생 시 신속히 대응하기 위한 운영 가이드다. 온콜 담당자는 본 런북을 기준으로 1차 대응한다.

## 대시보드
- 서비스 대시보드: Grafana(grafana.techcorp.example)에서 서비스별 상태 확인
- 인프라 대시보드: 노드·파드 리소스 사용량
- 비즈니스 대시보드: 주요 사용자 지표

## 주요 지표
- 가용성: 5xx 에러율, 헬스체크 성공률
- 지연: p50 / p95 / p99 응답 시간
- 처리량: 초당 요청 수(RPS)
- 리소스: CPU·메모리·디스크 사용률
- 큐: 메시지 적체량, 처리 지연

## 알람 기준
- 에러율 1% 초과(5분 지속) → 경고 알람
- 에러율 5% 초과 → 긴급 알람, 온콜 즉시 호출
- p99 지연 2초 초과 → 경고 알람
- 디스크 사용률 85% 초과 → 경고 알람

## 알람 대응 절차
1. 알람 확인(ack) 후 대시보드에서 영향 범위 파악
2. 최근 배포 이력 확인, 의심 시 롤백 검토
3. 로그·트레이스로 근본 원인 추적
4. 임시 완화(스케일 아웃, 트래픽 차단) 적용
5. 인시던트 채널에 경과 기록

## 알람 피로 관리
오탐이 잦은 알람은 임계값을 재조정하고, 무의미한 알람은 비활성화한다. 알람 규칙 변경은 PR로 관리한다.
