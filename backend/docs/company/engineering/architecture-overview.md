# 시스템 아키텍처 개요

## 전체 구성
서비스는 프론트엔드, API 게이트웨이, 마이크로서비스, 데이터 저장소로 구성된다. 모든 트래픽은 게이트웨이를 거쳐 인증·라우팅 후 내부 서비스로 전달된다.

## 주요 서비스
- 인증 서비스: 로그인·세션·토큰 발급 담당
- 사용자 서비스: 프로필·권한 관리
- 검색 서비스: 문서 인덱싱 및 RAG 질의 처리
- 알림 서비스: 이메일·푸시 발송

## 데이터 흐름
1. 클라이언트 요청이 게이트웨이에 도착
2. 게이트웨이가 인증 서비스로 토큰 검증
3. 검증 통과 시 해당 마이크로서비스로 라우팅
4. 서비스가 PostgreSQL 및 캐시(Redis)에서 데이터 조회
5. 응답을 게이트웨이가 취합해 클라이언트에 반환

## 비동기 처리
무거운 작업(인덱싱, 리포트 생성)은 메시지 큐에 적재 후 워커가 처리한다. 처리 결과는 알림 서비스로 통보한다.

## 배포 환경
- dev / staging / production 3단계 환경
- 컨테이너 기반 배포, Kubernetes로 오케스트레이션
- 인프라는 코드(IaC)로 관리

## 관측성
모든 서비스는 구조화 로그·메트릭·트레이스를 중앙 수집기로 전송한다. 상세 지표는 모니터링 런북을 참조한다.
