# 릴리스 프로세스

## 목적
안정적으로 제품을 배포하기 위한 릴리스 절차를 정의한다. 모든 배포는 본 프로세스를 따르며, 체크리스트 통과 없이 프로덕션 배포할 수 없다.

## 릴리스 단계
1. 코드 프리즈: 릴리스 브랜치 생성, 신규 기능 머지 중단
2. QA 검증: 스테이징에서 회귀 테스트 수행
3. 릴리스 노트 작성: 변경 사항·영향 범위 정리
4. 승인: 제품팀·엔지니어링 리드 승인
5. 프로덕션 배포: 점진적 롤아웃으로 진행
6. 배포 후 모니터링: 지표·알람 30분 관찰

## 릴리스 체크리스트
- [ ] 모든 테스트 통과
- [ ] 스테이징 검증 완료
- [ ] DB 마이그레이션 검토 및 롤백 계획 확인
- [ ] 릴리스 노트 작성
- [ ] 피처 플래그 설정 확인
- [ ] 롤백 절차 숙지
- [ ] 온콜 담당자 공지

## 롤백
배포 후 핵심 지표가 악화되면 즉시 롤백한다. 롤백 후 원인 분석을 진행하고 재배포 일정을 잡는다.

## 정기 배포
정기 배포는 주 2회(화·목) 오전에 진행하며, 금요일 오후와 주말 배포는 지양한다.
