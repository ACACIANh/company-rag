## 1. 아키텍처 & 레이어 경계

1. "`app/graph/nodes/`는 순수 함수다"라고 했는데, `permission`·`retrieve`·`generate`는 `async`이고 `core`를 통해 FGA·DB·LLM을 호출합니다. 이게 어떻게 순수 함수인가요? "순수 함수"의 정의를 무엇으로 잡으셨나요?
   ▶ State in→State out과 side-effect의 경계를 정확히 이해하는지. 말과 코드의 불일치.

2. `core/`가 LangGraph를 모른다는 규칙으로 무엇을 얻었나요? 실제로 오케스트레이터를 교체할 일이 있었나요, 없다면 이 추상화의 비용 대비 효용은?
   ▶ YAGNI vs 학습용 추상화. 결정을 방어할 수 있는지.

3. `app`이 `core`의 ABC만 의존한다지만 구현체는 `lifespan`에서 생성됩니다. `lifespan`은 결국 모든 구현체를 알아야 하죠. 이 조립 지점이 비대해지는 문제는 어떻게 관리하나요?

## 2. LangGraph 그래프 설계 (Self-RAG / 루프)

4. 환각 검증 실패 시 다시 `generate`로 돌아갑니다. **입력이 동일한데** 왜 다른 답이 나올 거라 기대하나요? temperature가 0이면 무한히 같은 답을 만들고 `retry_count≥3`까지 비용만 태우지 않나요?
   ▶ 재시도 루프가 "변화를 만드는 무언가" 없이 설계됐는지. 가장 날카로운 지점.

5. grade 실패 시 `increment_retry → rewrite_query`로 가는데, `rewrite_query`는 원본 `question` 기반입니다. 같은 질문에서 같은 재작성 → 같은 검색이면 무한 루프 아닌가요? 재작성에 다양성을 주는 장치가 있나요?

6. `relevance_score ≥ 0.5` 임계값의 근거는? 이 점수는 LLM이 매깁니다. LLM 점수의 **일관성/캘리브레이션**을 검증했나요? 0.49와 0.51이 재시도를 가르는데 그 경계가 의미 있나요?

7. 한 질문에 LLM이 rewrite·router·(multi_query)·grade·generate·hallucination으로 5~6회, 재시도까지 10회 이상 호출됩니다. p95 레이턴시와 건당 비용은? 이 구조가 실시간 챗봇에 적합한가요?
   ▶ "정교한 그래프"의 운영 현실. 측정해봤는지.

8. HITL `interrupt()`는 `agent`(도구 호출) 경로에만 있습니다. `doc_search`는 사내 문서를 **확인 없이 외부 LLM API로** 전송합니다. 정작 사람 확인이 필요한 건 어느 쪽인가요?
   ▶ HITL을 도구 호출에만 둔 설계 판단. 데이터 거버넌스 관점.

## 3. RAG 검색 품질

9. 고정 500자 / 50자 overlap 청킹은 마크다운 헤더·표·코드블록을 무시하고 자릅니다. 표 중간이 잘리면 품질이 어떻게 되나요? 왜 구조 인식(semantic) 청킹을 쓰지 않았나요?

10. reranker 기본값이 `NoOp`인데 `retrieve_top_k=20`을 `top_k=5`로 줄입니다. 리랭킹이 없으면 무슨 기준으로 15개를 버리나요? 단순 거리순 절단이면 `top_k=20` 검색 자체가 낭비 아닌가요?

11. `multi_query`로 분해 후 RRF 병합을 한다는데, reranker가 NoOp이면 병합 전략은? 분해의 효과를 측정한 지표가 있나요?

12. 임베딩이 OpenAI 1536차원에 묶여 있습니다. SentenceTransformer로 바꾸면 차원이 달라 **전체 재인덱싱**이 필요한데, 이게 정말 교체 가능한 추상화인가요?

## 4. FGA 권한제어

13. pre-filter를 `path = ANY($1)` **정확 매칭**으로 했습니다. 접근 가능 폴더가 수천 개면 이 배열과 `ListObjects` 비용은? prefix 매칭을 포기한 이유(private_flag)가 트리 상속 모델 자체를 무력화하는 것 아닌가요?
   ▶ 트리 모델을 설계해놓고 정확 매칭으로 평탄화한 모순.

14. FGA 캐시 TTL이 60초입니다. 권한 회수 후 **최대 60초간 문서 노출**됩니다. `invalidate`가 모든 권한 변경 경로에서 호출된다고 보장하나요? 60초의 근거는?

15. 권한 경계가 `path` 문자열에 의존합니다. 문서가 이동·리네임되면 `documents.path`와 FGA `folder` 식별자가 어긋나는데, 이 동기화는 누가 보장하나요?

16. Redis 대신 PostgreSQL TTL 캐시를 골랐습니다(ADR-0009). 권한 체크는 모든 검색의 핫패스인데, DB 캐시의 읽기 지연·커넥션 풀 경합은 측정했나요?

## 5. 인제스천 & 데이터 모델

17. 청크와 원본을 분리하고 `content_hash`로 버전을 올립니다. 원본이 바뀌면 **기존 청크는 어떻게 되나요?** 옛 버전 청크가 벡터 DB에 남아 검색되는 stale 문제는?
   ▶ 버전 관리가 원본에만 있고 청크 재인덱싱/삭제와 연결됐는지.

18. PDF는 페이지별 텍스트 추출 후 개행으로 잇는다고 했습니다. 다단 레이아웃·표·스캔 PDF는요? 추출 실패를 감지하고 깨진 텍스트의 임베딩을 막는 장치는?

19. `chunk_id`가 MD5 해시입니다. 동일 내용 청크가 다른 문서에 있으면 충돌해 덮어쓰기되지 않나요? path를 해시에 포함하나요?

## 6. 운영 · 확장성 · 신뢰성

20. checkpointer 기본이 `MemorySaver`, 운영은 `AsyncPostgresSaver`입니다. 워커 여러 개에서 `interrupt`로 멈춘 그래프를 다른 워커가 재개해야 하는데, dev/prod 불일치는 어떻게 잡았나요?

21. `cost_tracker`가 JSON 파일에 로깅합니다. 멀티 프로세스/워커에서 동시 쓰기 race는? 비용 집계의 정확성을 신뢰할 수 있나요?

22. `chat_history`를 10턴 윈도우로 자릅니다. 긴 대화의 앞부분 컨텍스트 손실은? 요약 압축을 넣지 않은 이유는?

23. 그래프가 `graph.ainvoke()`로 최종 상태를 반환하는데, 프론트는 `/chat/stream`으로 토큰을 SSE 스트리밍합니다. ainvoke는 완료 후 반환인데 토큰 단위 스트리밍을 어떻게 구현했나요?
   ▶ 스트리밍과 invoke 패턴의 정합성. 실제 구현을 아는지.

## 8. 테스트 · 평가

28. 에이전트 도구 실행(`justify_execute`)에 실제 도구(부작용·실패·타임아웃)를 붙이면 어디가 깨지나요? HITL `confirm→justify_execute→agent` 경로를 어떻게 통합 테스트했나요?
