# 환각 오탐 → 재생성 루프 & 스트리밍 중복 출력 수정 — 설계

- 날짜: 2026-06-01
- 상태: 설계 승인 대기
- 범위: ① 환각 검사 오탐 수정, ② 스트리밍 중복 출력 방어 (LLM LangSmith 계측 ③은 별도 백로그 `#dx`로 분리)

## 1. 배경 & 문제

프론트(`/chat/stream`)에서 "배포는 어떤 절차로 진행해?"(alice) 질문 시 **동일 답변이 3~4회 반복** 표시되는 버그가 보고됨. 비스트리밍 `POST /chat`은 마지막 `answer`만 반환해 정상이라 curl 테스트에서는 안 잡혔다.

LangSmith 트레이스(project `company-rag`)로 원인 확정:

```
generate            → 정상적인 배포 절차 답변 생성 (문서 기반)
check_hallucination → hallucination_passed=False, retry_count=1
route_after_hallucination → "generate" (재생성)
… retry_count 2, 3 까지 반복 후 save_memory (상한 도달)
```

두 가지 문제가 겹쳐 있다:

1. **환각 검사 오탐(근본 원인)** — `generate`(`RAG_GENERATE`: *"참고 문서: … 한국어로 답변하세요"*)는 제약이 거의 없어 문서 청크에 근거하되 **수사·일반론·부연("미사여구")을 덧붙인다.** `check_hallucination`은 답변이 문서에 충실한지 엄격히 보므로, 부풀린 표현이 "문서에 없는 내용"으로 판정되어 NO를 낸다. **근거 청크는 충분한데 생성 답변이 부풀려져 오탐**나는 구조. 재생성해도 입력(같은 문서+질문)이 동일해 비슷한 답이 나오고 또 오탐 → 루프가 교정 기능을 못 하고 상한까지 헛돈다.
2. **스트리밍 중복 출력(UX)** — `generate_node`가 매 재생성마다 같은 `token_queue`에 토큰을 흘리는데 이전 답변을 무효화하는 신호가 없어, 프론트가 토큰을 누적해 답변이 반복 표시된다.

## 2. 목표 / 비목표

**목표**
- 근거 있는 종합·요약 답변이 환각으로 오탐되지 않게 한다(진짜 날조 차단은 유지).
- 재생성이 일어나도 프론트에 답변이 중복 표시되지 않게 한다.
- 환각 판정 변경의 효과를 정량 측정할 수 있게 한다.

**비목표**
- Self-RAG 재생성 루프 자체의 제거(설계 변경 — 별도 ADR 사안).
- LLM 호출의 LangSmith 계측(`#dx`, 별도 백로그).
- 검색·라우팅·권한 등 다른 경로.

## 3. 설계 ① — 환각 오탐 수정 (생성·검사 목표 정렬)

`check`만 완화하면 generate가 계속 부풀리는 한 미봉책이고, 과도 완화 시 진짜 날조까지 통과한다. 원인을 **생성 쪽에서** 잡는다.

### 3.1 `generate`에 groundedness 제약 추가 (핵심)
`app/graph/prompts.py`의 `RAG_GENERATE`에 "제공된 문서 내용에 근거해 답하라. 문서에 없는 일반론·추측·불필요한 수사는 덧붙이지 말라"는 취지의 제약을 추가한다. 부풀림을 원천에서 억제 → `check` 통과율이 자연히 오르고 답변도 더 사실적·간결해진다.
- **균형 주의**: 제약이 과하면 답변이 건조해진다. "문서 근거 + 자연스러운 한국어"를 함께 명시해, 충실하면서도 충분한 답을 유도한다.

### 3.2 `check_hallucination` 기준 명확화 (보조)
`CHECK_HALLUCINATION`을 "문체·표현 방식이 아니라, 답변에 담긴 **사실 주장**이 문서에 근거하는지"를 보도록 명확화. 표현 다양성에 판정이 흔들리지 않게 한다. `check_hallucination_node` 코드 로직(`"YES" in response`)은 변경하지 않는다.

### 3.3 환각 회귀 케이스로 측정
"근거 있는 종합 답변은 통과, 문서에 없는 사실 날조는 차단"을 검증하는 케이스를 평가에 추가하고, 3.1·3.2 적용 전후를 비교한다. 측정 없이는 프롬프트 변경의 효과를 입증할 수 없다.
- 구현 시 `tests/eval`의 환각 판정 평가 수단(현 `questions.yaml`은 라우팅·검색용이라 환각 케이스 부재)을 점검해, 적합한 형태(별도 케이스셋 또는 노드 단위 단위테스트)로 추가한다. 정확한 형태는 구현 계획에서 확정.

## 4. 설계 ② — 스트리밍 중복 방어 (최종본만 스트림)

재생성이 몇 번 일어나든 **확정된 최종 답변 하나만** 스트림한다.

- **`generate_node`** (`app/graph/nodes/generate.py`): `token_queue` 토큰 방출 로직을 제거하고 항상 `llm.complete()`로 `answer`만 생성한다. 노드가 단순해지고 "내가 마지막 generate인가" 문제도 사라진다. (비스트리밍 `/chat`은 원래 `complete` 경로라 영향 없음.)
- **`stream_answer`** (`app/graph/builder.py`): `graph.ainvoke()`로 그래프를 끝까지 실행해 확정된 `final["answer"]`를 받은 뒤, 그것을 토큰 청크로 쪼개 `token_queue`에 흘리고 → `sources` → `done` 순으로 방출한다.
- **프론트**: 변경 없음(여전히 `token`/`sources`/`done` 이벤트 수신).

**트레이드오프(인지됨)**: 실제 LLM 토큰 스트리밍 → 완성 후 의사(pseudo) 스트리밍. 첫 글자까지 "전체 생성+검사" 시간만큼 지연된다. 단 ① 수정으로 재생성이 급감하면 지연도 줄어든다.

## 5. 검증

- **단위 테스트**
  - `generate_node`가 `token_queue`를 사용하지 않고 `complete`로 answer만 반환.
  - `stream_answer`가 최종 `answer`를 토큰으로 1회만 방출(중복 없음), `sources`/`done` 순서 유지.
  - 환각 회귀 케이스(3.3): 종합 답변 통과 / 날조 차단.
- **수동 (LangSmith 트레이스)**: "배포는 어떤 절차로 진행해?"(alice) → `generate` 재실행 0~1회로 감소, 프론트 답변 1개만 표시.
- **회귀**: 기존 전체 단위 테스트 통과.

## 6. 영향 파일

- `app/graph/prompts.py` — `RAG_GENERATE`(3.1), `CHECK_HALLUCINATION`(3.2)
- `app/graph/nodes/generate.py` — 큐 로직 제거(4)
- `app/graph/builder.py` — `stream_answer` 최종본 스트림(4)
- `tests/` — 위 단위 테스트 + 환각 회귀 케이스(5)

## 7. 리스크

- groundedness 제약 과다 → 답변 건조화. 측정(3.3)으로 균형점 확인.
- 의사 스트리밍 전환 → 첫 토큰 지연 증가. ①로 재생성이 줄면 완화.
- 환각 판정 완화 → 진짜 날조 통과 위험. "사실 주장 기준"(3.2)과 회귀 케이스(3.3)로 방어.
