## 핵심 문제 키워드

| 키워드 | 설명 |
|--------|------|
| **Multi-turn** | 사용자와 AI가 여러 차례 대화를 이어가는 상황 |
| **Contextual Ambiguity** | 문맥적 모호성 — "그건?", "다른 옵션은?" 처럼 핵심 정보를 생략하는 질문 |
| **Intent Evolution** | 의도의 진화 — 대화가 진행될수록 사용자 의도가 변화 |
| **Information Loss** | 정보 손실 — LLM이 긴 대화의 초기 맥락을 잊는 현상 |
| **Recency Bias** | 최신 편향 — 가장 최근 질문에만 집중하는 LLM 경향 |

## 솔루션 키워드

| 키워드 | 설명 |
|--------|------|
| **Query Rewriting** | 쿼리 재작성 — 사용자 질문을 검색 시스템이 이해하기 최적인 형태로 변환하는 과정 |
| **Query Rewriter** | RAG 파이프라인 앞단에 위치하는 재작성 모듈 |
| **Standalone Query** | 이전 대화 없이도 독립적으로 완전한 의미를 갖는 질문 형태 |

## 고급 기법 키워드

### Step-Back Prompting
- **개념**: 복잡한 질문에 바로 답하는 대신, 한 걸음 물러나(step back) 더 추상적인 상위 개념 질문을 먼저 생성
- **예시**: "특정 물리 문제 풀기" → "이 문제에 적용되는 물리 법칙은?"
- **장점**: 복잡한 추론이 필요한 전문 분야(과학, 법률)에서 깊이와 정확성 향상
- **단점**: 프롬프트 설계 까다로움, 추가 LLM 호출로 응답 시간·비용 증가

### HyDE (Hypothetical Document Embeddings)
- **개념**: 검색 패러다임을 `질문-문서 유사도` → `답변-문서 유사도`로 전환
- **동작**: 질문 → LLM이 이상적인 가상 답변 생성 → 가상 답변과 유사한 실제 문서 검색
- **장점**: 질문이 모호하거나 키워드가 부족할 때 의미적 의도를 파악해 관련 문서 발굴
- **단점**: LLM이 모르는 최신 정보·전문 용어에서 엉뚱한 가상 답변으로 검색 성능 저하

### Multi-Query
- **개념**: 복합 질문을 여러 개의 단일 관점 쿼리로 분해하는 전략
- **예시**: "레드삭스 vs 패트리어츠 최근 우승" → ["레드삭스 마지막 우승 연도?", "패트리어츠 마지막 우승 연도?"]
- **장점**: 여러 정보를 동시에 묻거나 비교 질문에서 포괄적 검색
- **단점**: 여러 번 쿼리 생성·검색으로 응답 시간·비용 증가

### RAG-Fusion
- **개념**: Multi-Query로 얻은 여러 검색 결과를 지능적으로 병합
- **핵심 알고리즘**: **RRF (Reciprocal Rank Fusion)** — 각 쿼리의 검색 순위를 역수로 계산해 합산, 최종 문서 순위 결정
- **장점**: 놓치는 정보 없이 신뢰성 높은 검색 결과 생성

## 아키텍처 키워드

| 키워드 | 설명 |
|--------|------|
| **Router** | 파이프라인 앞단에서 질문 복잡성을 분석해 최적 처리 전략을 동적으로 선택하는 LLM 노드 |
| **Adaptive RAG** | 적응형 RAG — 쿼리 특성에 따라 처리 방식을 동적으로 결정하는 아키텍처 |
| **Agentic RAG** | 에이전틱 RAG — 정해진 규칙을 벗어나 스스로 상황을 판단하고 전략을 선택하는 RAG |
| **Multi-hop Retrieval** | 멀티 홉 검색 — 여러 단계의 검색을 거쳐 정보를 수집하는 방식 |
| **Vector DB** | 임베딩 벡터를 저장·검색하는 데이터베이스 |
| **Similarity Threshold** | 검색 결과 필터링 기준 유사도 점수 (높일수록 정밀도 ↑, 검색량 ↓) |
| **Top-k** | 검색 시 반환할 최대 문서 수 |

## 구현 시 고려사항 (블로그 저자 실전 경험)

- **응답 속도 vs 품질 트레이드오프**: 기법을 많이 적용할수록 응답 시간 증가
- **Router LLM은 경량 모델로**: 속도·비용 절감을 위해 라우터 전용 경량 LLM 사용
- **Multi-hop + threshold ↑ + top-k ↓**: 속도 저하를 보상하는 파라미터 조정
- **점진적 도입 원칙**: 기본 재작성부터 시작 → 평가(eval) → 복잡한 기법 순차 추가
- **운영 복잡도 고려**: 파이프라인이 복잡할수록 유지보수 비용 증가
