# Decision: OpenFGA 호스팅 방식

**Date**: 2026-05-23
**Context**: RAG 챗봇의 접근 권한 제어에 사용할 OpenFGA 서버를 어디서 실행할지 결정

## Options

| 선택지 | 트레이드오프 |
|--------|------------|
| 로컬 Docker | 인프라 비용 없음, 직접 운영 필요, 사내망 내 데이터 유지 가능 |
| Auth0 FGA (클라우드) | 관리형 서비스로 운영 부담 없음, 외부 의존성 + 비용 발생 |

## Decision

**선택: Auth0 FGA (포트폴리오/개발 단계), 실운영 전환 시 로컬 Docker**

## Rationale

포트폴리오 목적으로 빠르게 동작을 확인하는 데는 Auth0 FGA가 적합하다. 실제 사내 운영 환경에서는 보안 정책상 외부 서비스 의존 없이 사내망 내에서 데이터를 유지해야 하므로 로컬 Docker로 전환한다. 코드는 환경 변수(FGA_API_URL)로 두 환경을 구분해 추상화 레이어를 유지한다.
