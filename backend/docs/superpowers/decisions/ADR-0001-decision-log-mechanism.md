# ADR-0001: 결정 기록 메커니즘 도입

> **Status**: 🟢 적용완료

**Date**: 2026-05-22
**Context**: superpowers 개발 흐름 중 AskUserQuestion으로 선택이 발생할 때 트레이드오프와 기준을 어떻게 기록할지 결정

## Options

| 선택지 | 트레이드오프 |
|--------|------------|
| 메모리 자동 기록 | 대화 간 지속되지만 코드베이스에 남지 않아 팀 공유 불가, git 히스토리 없음 |
| ADR 파일 (docs/ 커밋) | git 히스토리에 남고 팀 공유 가능, 파일 생성 오버헤드 있음 |
| 둘 다 | 중복 관리 부담 |

## Decision

**선택: ADR 파일 (docs/superpowers/decisions/ 에 커밋)**

## Rationale

git 히스토리에 남아야 "언제 왜 이 방향을 택했는지" 나중에 추적 가능. 팀원과 공유도 가능. 메모리는 대화 컨텍스트용이고 설계 결정은 코드베이스와 함께 버전 관리되는 것이 적합.

---

| 선택지 | 트레이드오프 |
|--------|------------|
| 모든 AskUserQuestion 직후 자동 | 누락 없지만 사소한 선택도 기록됨 |
| 중요한 결정에만 (Claude 판단) | 누락 가능성 있음 |
| 사용자가 명시적으로 요청할 때만 | 번거로움, 목적 달성 불가 |

## Decision

**선택: 모든 AskUserQuestion 직후 자동 (단, 단순 프롬프트 튜닝 제외)**

## Rationale

누락 방지가 목적이므로 자동이어야 의미 있음. 다만 모델명·포맷 등 자명한 선택은 제외해 노이즈를 줄이고, 설계·방향·도구 선택은 반드시 기록.
