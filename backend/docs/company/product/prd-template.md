# PRD 작성 템플릿

## 목적
제품 요구사항 문서(PRD)는 무엇을, 왜 만드는지 정렬하기 위한 문서다. 새 기능 개발 착수 전 PO가 작성하고 관련 팀과 리뷰한다.

## 섹션 구성
### 1. 개요
- 한 줄 요약
- 작성자 / 작성일 / 상태

### 2. 배경과 문제 정의
- 해결하려는 사용자 문제
- 현재 상황과 한계
- 관련 데이터·리서치 근거

### 3. 목표와 성공 지표
- 달성하려는 목표
- 측정 가능한 성공 지표(예: 전환율, 리텐션)
- 비목표(이번에 다루지 않는 범위)

### 4. 사용자 시나리오
- 주요 사용자 흐름
- 엣지 케이스

### 5. 요구사항
- 필수(Must) / 선택(Should) / 추후(Could) 분류
- 기능별 상세 명세

### 6. 디자인
- 와이어프레임·플로우 링크

### 7. 출시 계획
- 단계별 롤아웃 전략
- 의존성 및 리스크

## 작성 원칙
- 솔루션보다 문제를 먼저 정의한다.
- 측정 가능한 지표를 반드시 포함한다.
- 결정 사항과 미결정 사항을 명확히 구분한다.
