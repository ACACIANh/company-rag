# 시연 시나리오 설계

> **대상**: 비즈니스 관계자 / 투자자
> **형식**: 영상 녹화 (라이브 실행 방식)
> **목표 시간**: 약 6분

---

## 포지셔닝 메시지

> "오늘 보여드리는 건 완전 자율 에이전트가 아닙니다.
> 사람이 결정권을 유지하면서 AI가 실무를 지원하는,
> 대부분 기업이 지금 당장 도입 가능한 단계입니다."

이 시스템은 에이전트 도입의 **중간 단계**를 구현한다.
AI가 작업을 제안하고, 위험 작업은 사람이 승인하며, 접근 권한은 부서 단위로 정밀하게 제어된다.
"통제권을 잃지 않으면서 AI를 도입할 수 있다"는 신뢰가 핵심 메시지다.

## 10장면 대본

### 장면 ① — 권한 스냅샷 (0:00~0:30)
**계정**: minjun | **라우트**: capability | **도구 레이블**: `[권한]`

**입력**
> "내 현재 권한이 뭐야?"

**기대 출력**
- 인사팀 폴더 열람 가능, 법무·재무 폴더 없음
- SQL 권한: allow_select

**내레이션 포인트**: 권한이 무엇인지 먼저 확인 → 이후 차단 장면의 이유가 명확해짐

---

### 장면 ② — 온보딩 문서 검색 (0:30~1:10)
**계정**: minjun | **라우트**: doc_search | **도구 레이블**: `[RAG]`

**입력**
> "신입사원 온보딩 절차 알려줘"

**기대 출력**
- `/company/hr` 폴더 문서 검색 성공
- 온보딩 단계 요약 + 출처 청크 표시

**내레이션 포인트**: 자연어 질문 → 사내 문서 즉시 검색

---

### 장면 ③ — 라우터 명확화 (1:10~1:50)
**계정**: minjun | **라우트**: clarify | **도구 레이블**: -

**입력**
> "보안 문서 좀 알려줘"

**기대 출력**
- 챗봇이 되물음: "어떤 보안 문서를 찾고 계신가요? 개인정보 처리방침인가요, 사내 보안 정책인가요?"
- minjun이 "사내 보안 정책" 답변 → 정상 응답

**내레이션 포인트**: 모호한 질문은 추측하지 않고 명확화 요청 → 오답 방지

---

### 장면 ④ — 법무 문서 FGA 차단 (1:50~2:20)
**계정**: minjun | **라우트**: doc_search | **도구 레이블**: `[RAG]`

**입력**
> "표준 근로계약서 양식도 보여줘"

**기대 출력**
- `/company/legal` 폴더 → 법무팀 전용 → FGA 차단
- "해당 문서에 대한 접근 권한이 없습니다" 응답

**내레이션 포인트**: 장면 ①에서 예고된 권한 없음 → 차단이 납득됨

---

### 장면 ⑤ — 장비 현황 SQL 조회 (2:20~2:50)
**계정**: admin | **라우트**: agent | **도구 레이블**: `[SQL]`

**입력**
> "현재 미배정 노트북 목록 보여줘"

**기대 출력**
- `SELECT * FROM business.equipment WHERE category='노트북' AND status='미배정'`
- 마크다운 표로 결과 출력 (NB-001, NB-002 포함)

**내레이션 포인트**: 자연어 → SQL 자동 생성 → 결과 반환

---

### 장면 ⑥ — 장비 지급 + HITL 승인 (2:50~3:30)
**계정**: admin | **라우트**: agent | **도구 레이블**: `[SQL]`

**입력**
> "이민준에게 NB-001 지급해줘"

**기대 출력**
1. LLM이 employees에서 minjun의 emp_id 조회 후 UPDATE 계획 수립
2. HITL 팝업: `"UPDATE business.equipment SET ... WHERE asset_id='NB-001' — 실행할까요?"`
3. 관리자 승인 클릭
4. 실행 완료 메시지

**내레이션 포인트**: 위험 작업은 AI가 제안 → 사람이 최종 결정 (통제권 유지)

---

### 장면 ⑦ — 법무 문서 권한 부여 (3:30~4:00)
**계정**: admin | **라우트**: agent | **도구 레이블**: `[권한]`

**입력**
> "이민준에게 법무 문서 열람 권한 줘"

**기대 출력**
- permission_tool 실행
- "이민준에게 법무팀 열람 권한을 부여했습니다"

**내레이션 포인트**: 권한 관리도 자연어 한 줄

---

### 장면 ⑧ — 재검색 성공 (4:00~4:30)
**계정**: minjun | **라우트**: doc_search | **도구 레이블**: `[RAG]`

**입력**
> "표준 근로계약서 양식 보여줘"

**기대 출력**
- 이번엔 `/company/legal` 접근 성공
- 근로계약서 내용 요약 + 출처 표시

**내레이션 포인트**: 권한 부여 즉시 반영 — 재배포·재시작 없음

---

### 장면 ⑨ — 감사 기록 조회 (4:30~5:00)
**계정**: admin | **라우트**: agent | **도구 레이블**: `[감사]`

**입력**
> "최근 권한 변경 이력 보여줘"

**기대 출력**
- 장면 ⑦에서 이민준에게 법무팀 권한 부여한 이력 포함 감사 로그 표시

**내레이션 포인트**: 모든 권한 변경은 기록됨 → 감사 추적 가능

---

### 장면 ⑩ — 부서 관리자 권한 위임 (5:00~5:40)
**계정**: joohwan | **라우트**: agent | **도구 레이블**: `[권한]`

**입력**
> "미도를 개발팀에 추가해줘"

**기대 출력**
- 개발팀 admin 권한으로 멤버십 grant 성공

**(추가 옵션)** 이어서:
> "미도를 재무팀에도 추가해줘"
- "개발팀 외 부서 멤버십은 위임 권한이 없습니다" → 경계 명확히 시연

**내레이션 포인트**: 부서 관리자는 자기 부서만 위임 가능 → 권한 경계 세분화

## 선행 확인 사항

- 장면 ①: "내 현재 권한이 뭐야?" capability 라우트 정상 동작 확인
- 장면 ③: 모호한 질문으로 clarify 트리거 되는 입력 사전 테스트
- 장면 ⑥: HITL 팝업 정상 트리거 확인 (sql_rw + UPDATE 경로)
- 장면 ⑨: 감사 로그에 장면 ⑦ 이력이 실제로 기록되는지 확인
- 장면 ⑩: joohwan 계정으로 "재무팀 추가" 시 거부 응답 확인
- 영상 편집 시 계정 전환 장면에 자막 처리 권장
